## 仓库及同步边界

- 全站官方规则仍从 KazumiRules 自动同步到 D1，无需访客登录；自定义仓库不会改变全站地址、写入全站规则表或影响其他访客。
- 自定义仓库地址和所安装的规则保存在当前浏览器。读取目录不自动安装。可在列表中手动更新已从同一仓库安装的规则；启用 / 停用选择保留。编辑后另存的规则脱离原仓库更新关系。
- 相同名称且来源不同的规则不能被覆盖，包括官方订阅与手工粘贴的规则。安装文件中的订阅标记、来源地址和禁用状态不作为可信设置；来源由用户当前所选仓库决定。
- 网页服务器只读取 `https://raw.githubusercontent.com/` 的公开目录，拒绝其他域名、代理前缀、账号密码、查询参数、片段、特殊路径和重定向。此处比原生客户端更严格，避免将公开服务变成任意 URL 代理；没有开放任意 HTTP / 自托管仓库。
- 安装前核对有效索引、实际文件名、规则内名称、HTTPS 和现有解析兼容性。单个响应最多 1 MB、索引最多 500 条、安装规则最多 60 KB；一个安装请求最多读取索引和所选文件。请求有 16 秒总时限，使用既有规则接口限流；32 项内存缓存保留 5 分钟。
- KazumiRules 最新提交仍为 [`2967d7ba`](https://github.com/Predidit/KazumiRules/commit/2967d7babafffa92dbf35fbcb69d0fd964139e63)，与现有 18 条备用快照一致；本轮不重复修改快照。规则格式有效不代表每个第三方源当前均可播放。

## 验证

新增 `check-rule-repository.cjs` 执行实际规范化函数、安装合并逻辑、服务端读取器、API 路由和 React 组件事件，覆盖恶意 URL / 路径、索引完整性、同名保护、伪造订阅标记、禁用状态保留、官方同步保留本机规则、重定向与大响应拒绝、文件名错配、缓存，以及旧目录 / 安装请求晚返回。其余回归、类型检查与生产构建按发布流程运行。

线上首次验收发现 Workers 不实现 `redirect: 'error'`，目录读取因此报错；后续修正为 `manual` 并显式拒绝所有非 2xx 响应，不请求 Location。回归约束实际传输选项，避免只在 Node 替身上通过。全站原有规则同步不受此问题影响。

`scripts/fixtures/rule-repository/` 提供不含凭据的虚构目录与安装样例，使用 example.com，仅用于回归和线上读入 / 安装 / 更新验收，不是可播放的资源，也不自动加入全站规则。
