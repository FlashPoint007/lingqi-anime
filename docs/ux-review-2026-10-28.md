# Visitor experience review, 2026-10-28

Baseline: Site v118, native source `b439ece7a8a00a6123f8fb945345b132fd1029cb`; public GitHub `11dbc83cfb2a97dfe039061e67bd3e3e8402c79f`.

## Changes

1. **Search Back/Forward lost the preceding result.** In a fresh cloud browser, searching 高达 and then 咒术回战 replaced the sole website history entry; Back left the website for about:blank. Valid distinct search submissions now push their complete search route. Repeating the same search does not add a duplicate history step, and invalid syntax does not change history. Back/Forward restores the query, filters and page through the existing router.
2. **Public navigation waited for personal storage.** The initial route and public controls were gated on the account/library request, whose deadline can reach 15 seconds. Public search links, detail links and menu navigation now become available after client initialization. A watch/resume link still waits for the confirmed account scope before reading viewing history. Navigating away cancels that pending resume intent. Personal exclusion filters keep their own loading state and do not show unfiltered cached results while the account is unknown; personal filter controls remain disabled until ready.
3. **Collection filtering had no direct reset.** A clear-filter action now resets its title query and status filter, while retaining layout and sorting choices. The query length is bounded consistently with history search, and the result count is announced as status.

## Validation and remaining work

The new `check-user-navigation.cjs` first reproduced the history and public-bootstrap failures against production code. It covers distinct/duplicate/invalid searches, Back/Forward restoration, public deep links while personal storage is pending, account-safe deferred resume, cancellation by explicit navigation and safe personal-filter loading. Existing VM harnesses were updated to supply the new dependencies.

All 52 CJS regression scripts, TypeScript, foundational integration checks and the native build are required before publication. Final browser acceptance repeats search Back/Forward, collection clear-filter behavior and saved playback progress on the deployed version.

Email verification/password recovery is visibly not enabled and remains a future service integration. Real cross-device authenticated synchronization and physical Safari/mobile devices were not newly exercised. No claim is made that all upstream sources or all browsers are error-free.
