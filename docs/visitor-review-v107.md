# 普通访客流程抽查与修复（v107）

## 复现与修复

- 已有电影记录通过逐集进度续播、立即停止等待、返回后，找源占位状态的空地址覆盖原记录，刷新后记录被有效性校验丢弃。v106 线上已复现《你的名字。》约 82 秒的记录消失。现在初次创建记录和刷新进度都要求有效的非空播放地址与源页面地址；找源、停止和返回不再修改原进度，正常播放继续保存。
- 从搜索找到电影、加入“想看”、进入追番列表、刷新恢复、打开播放、失败后返回。v105 返回时丢失“我的追番”上下文，并显示“正在读取番剧…”。根因是路由把同 ID 的详情与剧集清空，而详情 effect 只依赖 ID，没有重新触发。修复为保留已有同 ID 详情与剧集，并在详情历史条目中记录来源页面；陌生分享链接仍回到发现页，不接受无效来源。
- 多个自定义别名占满四次查找名额，中文正式标题与原名被截掉。现在为去重后的正式标题和原名保留名额，其余名额优先尝试自定义别名，仍保持最多四个检索词。
- 手动播放/切线解析最多三条兄弟线路时，各自获得 35 秒，累计可达 105 秒。现在每次请求受现有恢复预算的剩余时间约束；回归复现三个 35 秒，再验证 35/35/20 秒。此预算针对本轮解析；播放器媒体初始化仍有自己的保护。
- 长按临时倍速及松开恢复直接写入 playbackRate，设备拒绝或忽略倍速时可能抛出异常，或显示没有生效的临时倍速。现在验证实际倍速，捕获设置和恢复失败，保留可用控制并给出提示。
- 未验证媒体的提示改为“尝试加载”，避免将经过站内代理的 HLS 错称为浏览器直连。

## 验证范围

新增 `check-visitor-review.cjs` 执行真实路由、源名生成、手动解析、历史记录与长按操作逻辑；五类问题均先复现失败再修复。既有用户流程回归继续覆盖慢详情下可播放、续作全局集数、错片恢复及历史续播。

云浏览器已验证首页、搜索、2025 冬季与当前季度切换、封面、想看状态与刷新恢复、下载页入口及 17 条全站规则，并复现电影播放失败后的返回问题。《你的名字。》已实际解码 1920×1080，时长约 106 分钟，进度正常增长；正常播放后返回也复现了分集清空与加载状态残留。发布后继续验收上述返回路径、正向播放、换集和历史恢复。片源目录与实际媒体可播分开判断；《超辉夜姬！》本轮自动检测未找到已确认的可播资源，不能据此宣称所有电影或所有源均可播放。

TypeScript 与 45 个回归脚本共 46 项检查；测试依赖模块不计入检查数。旧的分享链接测试补齐了路由所需的浏览器历史、当前详情及追番上下文，继续验证陌生分享链接不会自动播放。内部预览路由此前不可访问，本轮使用正式构建及上线后的云浏览器验收。
