# 2026-11-02 下载生命周期与用户流程复查

基于线上 v121（源码 `d10ad68e47170903605bd3abb28112b67d4fe141`）检查搜索、播放页、观看记录与下载任务，修复下载流程中可复现的错误。本轮不修改数据库结构、站点权限或媒体授权时长。

| 问题 | 触发与影响 | 修复及验证 |
| --- | --- | --- |
| 就绪任务误判视频授权有效期 | 原始媒体授权即将到期时准备下载，任务仍按“准备后 7 小时”判断，点击后拿到已过期链接 | 服务端返回原签名的实际到期时间；客户端和队列在交给浏览器前检查，预留 5 秒余量。缺少到期字段的旧任务重新准备。测试覆盖短有效期、旧记录、重新准备成功与禁止过期文件请求 |
| 单集下载重试重复使用旧签名地址 | 原有“下载到本地”记录只保存视频票据；稍后点击“重新准备”仍请求相同的过期票据 | 播放页传入实际播放规则，保存剧集源页面、集数、条目来源和媒体类型。重新准备先解析原剧集，再申请下载地址；自定义视频直链仍沿用直链。测试验证请求顺序与上下文保留 |
| 单集下载检查无限等待、网关提示难懂 | 请求仅有手动取消信号；网络不返回时一直显示检查中，HTML 网关错误直接暴露 JSON 解析异常 | 下载检查组合手动取消与 30 秒截止时间，并复用本站请求错误处理。测试模拟无响应网络与 HTML 503 |

下载准备完成后还会核对当前账户与剧集上下文，过期的“点击重新下载”链接也经过统一检查。组件回归覆盖切换账户后不启动旧下载、不写入旧完成状态，以及新请求保留正确来源。

六个新增生命周期场景与服务端授权到期断言先在原实现上失败，修复后通过。56 项 CJS 回归脚本、TypeScript 和 `check-web.mjs` 均通过；包括 17 条有效规则、解析、签名 HLS、范围响应和下载 ZIP 完整性检查。正式发布使用原生构建。
