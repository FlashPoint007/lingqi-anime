# 搜索、播放与加载体验抽查（v104基线）

## 本轮修复

1. **搜索误删标题标点。** 线上输入`银魂'`，提交后标题变成`银魂`；英文`It's`也会被拆开。旧正则还可能把普通标题中的撇号与后面的`tag:'原创'`配成一组。改为只在词首或明确条件值处识别成对引号，保留普通标题的撇号；多段引号短语逐段解包，未闭合的条件引号给出错误，不静默吞字。
2. **资料不全时重复检测片源。** 卡片同时缺少集数和类型时先启动检测，详情返回后作用域变化又取消重跑。现在仅在资料仍加载且这两项都未知时暂缓自动检测；任一项已有时仍可并行检测并启动已就绪的剧集，不等待慢详情。完全缺乏匹配资料时自动播放入口才等待，避免以不完整信息判断同名作品。真实Hook回归先复现提前启动3个任务，再验证延迟期间为0、资料就绪后只启动正常的3个并发任务；已有慢详情不阻塞可播剧集的检查继续保留。
3. **首次找源没有消耗恢复预算。** 原先首次找源耗时不计入恢复窗口，第一次播放错误又获得新的90秒。现在首次找源和随后自动恢复共享窗口；确认播放成功后，未来的新卡顿仍可获得独立窗口，手动重试也可重开窗口。不改变媒体初始化自己的空闲/绝对超时保护。
4. **HLS内核选择错误。** 部分CDN的`.mp4`路径实际返回HLS，或跳转到`.m3u8`。原解析器只按原地址后缀选择内核。现在检测响应MIME和最终地址，并验证`#EXTM3U`正文，将实际类型传给播放器；不会把这种HLS走成稀饭的原生MP4直连捷径。不是仅凭MIME就认定播放列表有效。

## 验证

- TypeScript与44个回归脚本，共45项；关键回归先复现失败再修复。`check-search-playback-ux.cjs`覆盖标题撇号、混合快捷条件、引号短语和共享找源预算；既有Hook与解析/API脚本覆盖检测调度、伪装HLS、跳转和实际播放器类型。
- 云浏览器抽查中文、日文、英文和续作标题；发布前《Fate/Zero》25集目录可加载，首集实际解码1920×1080并持续增长进度。发布后继续核对标点保留、快速切换搜索、空结果、详情/返回以及播放与换集。
- 无新依赖、数据库迁移、后台任务或个人数据清理。内部预览此前连接受限，本轮使用生产构建及正式站云浏览器验收，不将模拟上游回归当作所有第三方媒体都已可播。

片源目录匹配不等于媒体播放成功；上游验证、失效媒体和浏览器编码支持仍需逐条实测。本轮类型识别修复不代表已确定此前《地狱乐 第二季》所有线路失败的根因。
