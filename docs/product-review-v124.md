# v124：从找片到续播的产品体验复查

基于 v123（源码 `08e48adf38c5e1ca02a3c1e7bd86c7d0dbbba536`）检查首页、搜索、详情、片源检测、播放及回访。优先减少完成观看目标所需的操作，而不是继续堆叠设置。

| 问题 | 用户影响与本轮改进 |
| --- | --- |
| 首页缺少回访续播入口 | 有观看记录仍需进入记录页寻找。首页增加最多 3 部尚未到结尾的作品，显示集数、上次位置与已知总时长，并直接复用原有解析/恢复流程。已标为看过、弃番、自定义测试视频不进入推荐；个人空间未就绪或隐身时隐藏。关闭自动恢复时按钮明确为“从头播放”。 |
| 后台检测锁住手动选源 | v123 中“待检测/检测中”的片源按钮被停用，即使用户知道可用源，也要等待排队。现在可以直接点击；点击后取消后台检测，保留已经完成的结果，立即搜索所选源。取消后的迟到结果不能覆盖当前状态；显式重新检测仍可恢复扫描，手动请求进行中继续防止重复点击。取消浏览器请求不保证第三方或服务器端已开始的共用请求立即停止，仍保留现有限流与短暂重试。 |
| 续播文案与实际行为不一致 | 接近结尾的视频会被播放器从头播放，但按钮仍写“继续播放”；关闭自动恢复后也有同样误导。记录页与详情使用和播放器相同的 5 秒结尾保护显示“重新播放/重新观看”，关闭自动恢复时显示从头播放。重看中的旧完成标记不会误隐藏当前进度。详情的播放入口在个人空间读取期间停用，避免使用正在切换的旧记录。 |

## 验证

`check-product-flow.cjs` 执行实际续播筛选、组件事件和 Home 的选源回调，覆盖排序、去重、已看/弃番排除、结尾与重看、个人空间/隐身隐藏、从头播放文案以及所选源索引交接。`check-availability-hook.cjs` 增加取消检测、迟到结果和重新开始检测的真实 hook 回归。原有全部回归、TypeScript、18 条规则解析检查与正式构建继续执行。

云浏览器重点验收：打开详情后无需等待全部检测即可手动选源；实际播放、暂停、返回首页后出现续播卡片；卡片恢复至原集和进度。无观看记录不出现空白占位。布局使用响应式三/二/单列，沿用现有站点配色。

## 后续产品优先级

1. 完成邮箱发信服务的真实配置和验收，确保注册验证与密码找回可用；代码存在不等于邮件已经投递。
2. 持续按实际播放结果改善片源成功率与错误解释。“目录有分集”继续与“本集可播放”区分，不保证被源站限制的线路可用。
3. 在真实手机与投屏接收器上补充兼容性验收；本轮桌面云浏览器与模拟能力测试不能替代实机。

没有新增账号、公开评论、外部凭证或全站设置；续播卡片只读取现有个人记录，不新增数据库表或追踪数据。
