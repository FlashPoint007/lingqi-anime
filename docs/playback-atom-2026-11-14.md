# giriGiriLove Atom 播放页复查（2026-11-14）

## 线上失败与根因

v132 已兼容规则 2.7 的 `episodePage` 地址和跨域目录验证，但云浏览器中《葬送的芙莉莲 第二季》仍返回“此线路未解析到可播放的视频地址”。搜索与 cht / chs 分集目录均正常，问题发生在播放页解析阶段。

本次通过规则中公开的 `get_list`、`get_detail` 接口获取该番剧（source `26879`）及 cht 首集。官方包装页返回 HTTP 200、1554 字节 HTML，只有 Atom 容器和外部播放器脚本，没有媒体字面量。`scripts/fixtures/giri-atom-shell.html` 保留识别所需的最小结构，移除了样式、统计脚本和其他无关内容。

读取 [官方 Atom 脚本](https://pl.girigirilove.com/addons/aplyer/atom.obfuscated.js) 后，仅以本地静态字符串表解码核对参数流，没有执行远端脚本：脚本从当前页面查询参数读取 `url`，直接作为播放器的视频地址。没有发现需要交换的鉴权令牌或媒体解密步骤。所检查脚本 SHA-256：`481482dcbf73c097ce5ebfa867579534ed6b39fb660d05ca7b194c625eaccef3`。

原始媒体地址在正常请求及携带包装页 Referer 时均返回 HTTP 200、`video/mp4`，响应头部包含 MP4 `ftyp` 标记；未下载整集。

## 修复边界

- 仅适用于 giriGiriLove 官方源与固定 Atom 页面，不把普通页面的 `url` 参数泛化成媒体。
- 仍由服务端重新读取当前源站分集目录，完整匹配包装页 URL，授予本次请求的精确访问权限。
- 必须先正常请求包装页、通过页面错误和验证页检查，并识别 Atom 容器及脚本声明，之后才读取参数。拒绝重定向后的不同页面、缺失或重复参数、其他主机与路径。
- 参数中的地址仍须通过公共 HTTPS、端口与媒体路径校验；媒体请求和后续重定向保持原有安全限制。没有执行脚本、引入源站 Cookie 或绕过验证。

## 验证
