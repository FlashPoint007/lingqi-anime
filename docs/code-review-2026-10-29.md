# 2026-10-29 程序代码复查

基于线上 v120 对账号认证、个人记录权限/同步、公开目录缓存、规则输入与视频代理的关键路径进行复查。四个新增回归场景先在原实现上失败，再在修复后通过；本轮不修改数据库结构。

| 问题 | 触发与影响 | 修复 | 验证 |
| --- | --- | --- | --- |
| 新登录会话被数量限制误删 | 同一账号已有 10 个会话，且到期时间与新会话相同。仅按到期时间排序会删除刚签发的第 11 个会话，出现登录响应成功而下一次请求未登录 | 裁剪时明确保留返回给当前请求的新凭证，其他会话最多保留 9 个，并为相同到期时间增加稳定排序 | 真实 SQLite + Web Crypto，预置同到期时间的旧会话，确认新 cookie 可识别且总会话数仍为 10 |
| 失败登录积累过期的数据库限流记录 | 旧清理逻辑只在成功登录或成功受理邮件后执行；持续失败或额度拒绝的流量不能回收过期记录 | 对经过格式校验的登录和邮件申请都安排有界的后台清理，同一 Worker 中避免并发重复清理；继续保留限流与私有信息脱敏 | 预置过期限流行，执行未知账号失败登录，确认后台清理完成且请求仍返回 401 |
| 邮箱补验后账号状态停留在初始值 | 个人库刷新收到同一账号的新 `emailVerified` 值，状态回调仍捕获初始账号对象 | 每次持久化最新同步快照时更新账号元数据，焦点返回、手动或周期刷新均使用新状态 | 实际 React hook 模拟测试，验证同一账号由未验证变为已验证，无需重载；原有账号切换和离线补传仍通过 |
| 视频源停止传输后代理一直等待 | 源站已返回成功响应头，但后续流读取一直不返回；原来的连接超时已在收到头部时取消，无法终止卡住的传输及释放活跃响应名额 | 对正在进行的视频读取设置 30 秒空闲超时，超时/请求取消/下游取消时终止上游 reader；不设置整段影片总时长上限，保留流式背压和范围响应 | 新的流测试通过实际 `proxyMedia` 与 `secureResponse`，验证超时、Abort、取消均清理资源并释放名额；正常分段读取、206/Content-Range、HEAD 均保持正确 |

修复涉及 `lib/email-auth.ts`、`components/useLibrarySync.ts` 和 `lib/playback-server.ts`。对应回归为 `check-email-recovery.cjs`、`check-library-hook.cjs`、新增的 `check-stream-liveness.cjs`。

## 检查范围与结果

检查了同源 JSON 写请求、请求体大小限制、会话轮换/过期、单次邮箱令牌事务、个人数据账号 ID 绑定、评论和弹幕所有权、公开缓存与私有记录分离、公开 HTTPS 地址/重定向校验、签名媒体票据、HLS 重写规模限制，以及下载响应的范围/长度校验。现有相关权限和边界回归均继续通过。本轮没有复现跨账号读取或未授权写入；这不是对全站不存在其他漏洞的保证，也不等于真实 DDoS 压测。

55 项 CJS 回归脚本、TypeScript、`check-web.mjs` 和差异空白检查通过。正式发布前执行原生构建。浏览器抽查首页、芙莉莲搜索及加载中切换到 2026 年夏季时间表，结果标题和季度路由正确。发布后补查真实线路播放。

运行日志中观察到的 `/robots.txt` 和 `/sitemap.xml` 404 为爬虫请求，未将其误报为首页或播放接口崩溃。

邮箱发信服务仍缺实际发信配置：本轮账号边界使用模拟邮件和本地数据库验证，未在生产批量创建账号或发送邮件。真实发信验收仍需配置 `RESEND_API_KEY` 和 `LINGQI_MAIL_FROM`。外部视频源限制、Safari/移动设备和未抽查线路仍需各自验证。
