# Homepage interaction review, 2026-10-28

Baseline: Site v117, native source `55f8a3a657bfeabb3ba7f00916c5f30771933c6f`; public GitHub `a9508a08b552c26a22498cd16d0767a33fbe4203`.

## Confirmed fixes

- Background recommendation revalidation reset the manually selected card to the first item. Manual refresh also reset it before the request finished. The request now retains the current quarter's visible data and selects the same subject by ID when refreshed popularity order arrives. A subject removed from the valid result falls back to the first remaining item; another quarter never inherits the old cards.
- Opening a subject dialog did not suspend its underlying carousel. In the production browser the dialog remained on 学生会也有洞！ while the background recommendation advanced to 赛博朋克：边缘行者 2. The page now explicitly marks recommendations inactive while a detail dialog is open. Rotation and next-cover prefetch also stop when the carousel leaves the viewport, and resume when visible again. Observers and timers are cleaned up on unmount.
- The motion-preference effect called `MediaQueryList.addEventListener` unconditionally. A browser exposing only the legacy `addListener` API would throw during homepage setup. Both listener APIs are supported, with cleanup, and absent optional media-query/intersection APIs no longer crash the component.
