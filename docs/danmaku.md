# Danmaku

## Site-authored comments

The player includes **发弹幕**, a local preview/editor with rolling, top and bottom modes, preset/custom colors, and an editable video timestamp. Visitors can draft locally; publishing requires the site's email account. A short public-content notice is shown before sending. No message is forwarded to BiliBili, Gamer or Dandanplay, and those providers' availability does not affect site-authored comments.

Comments are stored as structured records in the D1 `site_danmaku` table, separately scoped to Bangumi subject ID and an explicit episode number (including episode 0 and fractional episodes). Unknown-number/manual test videos cannot publish. The public response exposes text, style and timing, never author email or another user's account ID. “我在本集发送的弹幕” provides private 20-row paging and an explicit confirmation to withdraw one's own comments. Withdrawal removes the public text, while the timestamp/mutation tombstone remains for quota and retry integrity.

`GET /api/site-danmaku?subject=…&episode=…&time=…` reads a bounded timeline window, returning at most 500 comments nearest the current position. Playback refreshes approximately every five seconds; paused playback uses 15 seconds. Hidden tabs stop polling, seeks cancel an obsolete read, and changing episode/account clears the previous scope. This is a timestamped comment feed rather than a live chat or WebSocket stream. Site comments keep actual video timing even when upstream comments use a manual offset, and respect the existing source/mode/keyword/regex display filters.

`POST /api/site-danmaku` accepts a maximum 4 KB JSON request, a stable mutation UUID, the expected current account ID, validated content (1–80 Unicode characters), time (0–86400 seconds), mode and RGB color. Exact Origin/JSON/session/ownership checks apply. A single atomic SQLite statement enforces a ten-second cooldown and 200 submissions per account per rolling day, including withdrawn comments. Retrying an accepted mutation returns the original record; a changed or withdrawn mutation cannot recreate content. Mutations and reads use `private, no-store` responses. The existing shared request guard also limits this endpoint.

Editing pauses video by default; this preference is normalized with existing danmaku settings and follows the account's settings sync. Successful send or explicit close resumes only a pause owned by this editor. An already-paused video, source change, player disposal, background tab, manual playback or expired sleep timer prevents that automatic resume. The preview and rendered comments use plain React/canvas text. Input-method composition cannot accidentally submit a message.

The watch player retrieves real episode comments asynchronously, without delaying video playback. BiliBili's public media/season metadata and XML comment endpoints are supported directly. Gamer's public episode/danmu endpoints are supported, but may reject requests or impose regional restrictions; failures are shown, not bypassed. No video files, comment author IDs, cookies or provider credentials are cached. Only normalized public comment text, timing, display mode, colour and origin are stored in the existing bounded D1 shared cache.

Automatic matching uses the exact Bangumi subject ID in small monthly files from [bangumi-data](https://github.com/bangumi-data/bangumi-data), licensed under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Attribution is also present in the player. The index is reduced to provider IDs and display titles. The broadcast month and adjacent months are checked; titles and season positions are never guessed. Episode numbers must match a unique numbered provider episode. Specials or unknown video episode numbers require explicit selection.

Kazumi's BiliBili/Gamer/弹弹play switches filter comment origins in Dandanplay's aggregated response; they are not three independent crawlers. To enable the same aggregation legally, obtain this site's own approved credentials from [Dandanplay's developer service](https://dev.dandanplay.com/), then set server-only secret environment values `LINGQI_DANDAN_APP_ID` and `LINGQI_DANDAN_APP_SECRET`. Do not reuse Kazumi credentials. The request signature follows the [official protocol](https://doc.dandanplay.com/open/): Base64(SHA256(AppId + timestamp + URL pathname + AppSecret)). Credentials never enter client bundles, database values, query strings or logs. Without both values, the UI explains the configuration requirement; Gamer, BiliBili and local imports remain independently available subject to provider access. These credentials are optional; do not change existing authentication/media secrets.

Users can also paste an official BiliBili bangumi URL (`md`, `ss`, `ep`) or a Gamer anime-video URL and select the correct episode. Explicit BiliBili XML/CID links and Gamer per-video links can load the selected comment file without guessing a season directory. XML (BiliBili) and JSON (Dandanplay compact `p`/`m`) imports up to 5 MB remain in browser memory and are cleared on episode changes. External entities, unsupported modes and invalid times are rejected/omitted. Text is painted as plain canvas text; remote HTML/scripts are never evaluated.

Settings include visibility, origin filters, opacity, font size, screen coverage, scrolling speed, time offset and literal keyword blocking. The subsequent upstream review added independent scrolling/top/bottom visibility, white-only rendering, and optional merging of identical text within 10 seconds. Display filters do not refetch or modify the source cache. A positive offset delays comments. Layout uses the media clock, clears on seek/resize and follows pause and playback speed. A canvas overlays both ordinary and Anime4K video inside fullscreen; native picture-in-picture and remote casting show the original video only. High-density episodes are uniformly sampled across the complete episode into a response under 192 KB; source counts/sampling status are visible. Lane scheduling further limits overlap.

The `/api/danmaku` endpoint is rate/concurrency limited by the existing metadata guard. It accepts fixed provider IDs and validated operations, never arbitrary fetch destinations or redirect targets. Provider requests and bodies have time/size ceilings. Successful episodes/comments use D1 with stale fallback. A failed partial index lookup is not stored as a successful empty match. Refresh bypasses freshness checks but retains rate limits.

Production acceptance on 2026-10-20 (v57): Gamer automatic matching returned all 28 Frieren episodes and 3,001 real first-episode comments, uniformly sampled to 2,400. The ACG-to-video identifier correction below resolved the previous catalogue failure. BiliBili still returned HTTP 412; Dandanplay remains unavailable until this site has its own approved credentials. A public test clip was used to independently verify remote comment rendering; this acceptance did not establish anime-media availability for every video source.

## Source failures and setup

The player now tries each provider from the **same exact subject match** once when automatic retrieval fails, returns a valid empty result, or lacks the exact episode. It never guesses the next provider's first episode. Explicit provider URLs/episode choices remain manual and do not fall through. Each failure stays visible; an unavailable service is not described as a show without resources.

Gamer requests include the public comment-catalogue `geo=TW,HK` parameter used by the reference implementation; this does not send a false client-country header or grant region/authentication privileges. Payloads with the documented nested `data` wrapper and a single nonstandard episode group are recognized. Error objects, maintenance HTML and invalid payloads are not stored as empty comments. Region/authentication denials are reported.

Source errors have structured codes (`UPSTREAM_BLOCKED`, `UPSTREAM_MAINTENANCE`, `UPSTREAM_REGION`, `UPSTREAM_AUTH`, `UPSTREAM_RATE_LIMIT`, `UPSTREAM_FORMAT`, `UPSTREAM_TIMEOUT`). Brief per-origin, per-isolate cooldowns reduce repeated calls after a rejection/maintenance/rate limit. A `Retry-After` response is honoured (including an HTTP-date). No cookie harvesting, borrowed app credentials, client-location spoofing, proxy rotation or security-challenge bypass is used. Changing the UI or adding a database cannot itself remove a provider's refusal of the hosted server.

Dandanplay setup requires an external approval step:

1. Open <https://dev.dandanplay.com/> and register a developer account, verify email and complete developer details.
2. Create an application for **零柒番剧**, supplying the site's URL and this GitHub repository, explain that users retrieve comments when playing a selected episode, with caching and request limits. Submit it for review. The service assigns the tier/quota; approval and availability are not guaranteed by this implementation.
3. After approval, configure the site's production **secret** environment values `LINGQI_DANDAN_APP_ID` and `LINGQI_DANDAN_APP_SECRET`. Use this site's assigned credentials, not Kazumi's. Never paste secrets into the public repository, a screenshot, or a browser-visible setting.
4. Redeploy to apply the environment revision. Open a real episode and confirm subject match, episode selection and a nonzero remote comment response. Merely filling the variables or passing a local file-import test does not count as verifying the service.

Suggested application description (adjust it to actual use before submitting): “零柒番剧是免费的网页番剧索引与播放器。计划在用户选择番剧分集并播放时，按需获取并显示该集弹幕；不批量抓取弹幕库，不提供弹幕付费下载。服务端保管应用凭证，缓存公开弹幕并限制请求频率。”

Reference: [official Dandanplay access and signature documentation](https://doc.dandanplay.com/open/). Application approval/terms and assigned quotas are managed by that service. Ordinary site visitors do not need their own developer account. No account was registered or application submitted on the owner's behalf.

## Gamer identifier correction

The `gamer` ID in bangumi-data identifies `acg.gamer.com.tw/acgDetail.php?s=...`, not an episode. These namespaces must never be interchanged. The matcher now searches the official Gamer catalogue using the indexed Traditional Chinese/original title, joins **exactly** on `acg_sn`, and takes the returned `video_sn` to request the episode directory. An explicit indexed `video_sn` can be used directly. A same-title search result with another ACG ID is rejected. If the join fails, the UI explains the conversion/source error; it never sends the ACG ID as `videoSn`. The shared match cache namespace was changed to invalidate old incorrect matches.

Kazumi credential review (2026-10-20): `lib/utils/dandan_credentials.dart` contains `String.fromEnvironment` placeholders. `.github/workflows/release.yaml` and `pr.yaml` inject `DANDANAPI_APPID` / `DANDANAPI_KEY` from private GitHub Secrets. The public source license is not evidence of permission to share those application credentials. No Kazumi binary was inspected to extract credentials and no borrowed application identity was configured. Reuse would require a real credential and explicit authorization covering this separately hosted site.


## Ratings, per-title search and offline comments (2026-10-27)

Bangumi ratings are public read-only metadata. Cards, favourites, subject details and the watch header identify the Bangumi score; details include the available voter count/rank and a link to the original subject. Missing/invalid scores are not displayed as zero. No local voting endpoint, personal score, Bangumi OAuth token or score mutation was added.

In **弹幕设置 → 按番剧检索弹幕**, visitors can search the current subject's broadcast-month index (including neighbouring months), BiliBili, Gamer or the signed Dandanplay v2 episode-search endpoint. Search results never start playback or silently select an episode: choosing a title fetches its full episode catalogue, then requires the existing exact episode logic/manual confirmation. Server destinations are fixed, input/results bounded and errors remain visible. Dandanplay still requires this site's own approved credentials; search UI does not remove upstream 412, maintenance or authentication restrictions.

Each subject retains up to five recent keywords in this browser, with separate account scopes, up to 100 subjects per account and ten recent local account scopes. Private playback mode neither loads nor writes this history. Changing subject/account/provider or stopping a search aborts its request; late results cannot enter a new scope. A clear action removes only that subject's history. This history is intentionally local and is not claimed to sync to D1.

**保存到站内离线库** now attempts a bounded comment snapshot after video completion, for individual and queued downloads. The current episode's selected/imported, filtered/converted comments and baked time offset are preferred when available; otherwise exact Bangumi/provider/episode matching is used. Public site comments are additionally loaded through `GET /api/site-danmaku?subject=…&episode=…&offline=1`, beyond the live playback window. This response contains no author IDs or account management fields, reads at most 5,001 rows, and uniformly reduces the first 5,000 to the usual bounded snapshot. Dense episodes are explicitly marked as a simplified snapshot rather than a complete archive. Video completion survives all optional comment failures; existing downloads offer **补存离线弹幕 / 更新离线弹幕**.

Snapshots are attached to the download's IndexedDB record with one owner-checked transaction. They cannot overwrite progress, re-create a deleted download, or replace a newer snapshot with an older write. No database schema migration, server-side video storage or additional service credential is needed. Deleting a download removes its attached comments. Clearing browser website data removes all local video/comments.

The standalone **离线放映室** caches the local comment renderer with the offline shell. It reads no remote API during playback, follows pause/seek/speed changes, supports an on/off switch and fullscreen for both video and canvas. XML/JSON files up to 5 MB can be imported into the selected download and persisted locally. The online player also exports the current displayed comments as an escaped XML file with its time correction; native browser video downloads remain ordinary video/ZIP downloads, with XML saved separately when requested by the visitor. Native video-only fullscreen, PiP or casting may exclude overlays; the dedicated fullscreen button includes them when the browser supports the Fullscreen API.

Validation: `scripts/check-rating-offline-search.cjs`, the existing offline player/download regressions and SQLite-backed site-comment tests exercise title/account/private-mode races, signed search, explicit source IDs, XML escaping, exact-episode capture, offline rendering, atomic writes and full-timeline public snapshots. Production browser observations are reported separately from simulated API/storage regression fixtures.
