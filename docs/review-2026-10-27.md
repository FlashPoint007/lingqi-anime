# User-flow review, 2026-10-27

Baseline: Site v114, native source `7168e8b89f1a140accd2c04064d9c7b0a56a865b`; public GitHub `b9222313e0ccabf216b1541b1f254eb7bc12dee4`.

## Confirmed fixes

1. A failed or partial offline-comment refresh could replace a valid saved snapshot with an empty/unavailable or incomplete result. The atomic writer now keeps the good snapshot, reports why it was retained, and still permits first-time failure status and fully successful replacement. Ownership, completed-video status, monotonic writes and existing playback progress remain enforced in the same transaction.
2. Automatic comment capture used completion time as its freshness marker. A slow old fetch could therefore replace a newer explicit local import. Capture now retains the request's start time, and a stale writer reports that the newer snapshot was retained.
3. Two local XML/JSON imports could finish out of order. The offline player now scopes file reads/writes/messages to both the current playback and the newest file selection. Late files and errors cannot replace a subsequent selection.
4. Browser Back/Forward changed an offline download URL without changing the playing item. Hash navigation now saves/clears the previous item, validates current ownership/completion, opens the requested record, and closes playback when returning to the bare library. Slow obsolete lookups cannot reopen an old item or show a late error.
5. The standalone player ignored the global automatic-resume setting. Reopening now starts at zero when resume is disabled; compatible HLS fallback follows the same preference while retaining an already decoded session's current position.
6. One production winter-calendar request returned 503 after approximately 2,002 ms, consistent with the existing bounded quota-storage check; a subsequent navigation recovered the cached archive. Read-only relative API GETs now retry that specific structured busy response once, only with a short valid Retry-After, and respect cancellation. Mutations, quota rejection, malformed gateways and arbitrary errors are not retried. The server's fail-closed quota check, shared limits and concurrency limits were not relaxed.
7. Offline `.mjs` JavaScript modules were unnecessarily treated as ordinary pages by the request guard. They now follow the existing `.js` static-asset policy. API allowlisting and HTTP-method checks still run first; POST and unknown API paths remain rejected. A v4 transfer entry and shell cache version 9 prevent the updated app from reusing an older cached writer; v3 remains a compatibility export.

The initial suspected character-credit issue was ruled out: the actual detail page already keys `SubjectPeople` by subject ID. No character component change was retained.
