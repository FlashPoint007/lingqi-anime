## 弹弹play 凭证结论

Kazumi 的 `lib/utils/dandan_credentials.dart` 只含 `String.fromEnvironment`，`.github/workflows/release.yaml` / `pr.yaml` 由私有 GitHub Secrets 注入实际值。公开源码不包含可直接复制的已授权凭证，代码 GPL 许可证也不自动授予第三方服务的应用身份或配额。没有提取发布二进制中的密钥，没有将 Kazumi 身份配置到本站。只有实际取得且明确授权覆盖本站的凭证才能复用；否则配置本站申请的 `LINGQI_DANDAN_APP_ID` / `LINGQI_DANDAN_APP_SECRET`，服务端签名。

参考：[上游](https://github.com/Predidit/Kazumi)、[发布流程](https://github.com/Predidit/Kazumi/blob/main/.github/workflows/release.yaml)、[弹弹play 官方接入说明](https://doc.dandanplay.com/open/)。详细设置见 [danmaku.md](danmaku.md)。

## 2026-10-21 播放恢复复查

线上复现芙莉莲第二季第 29 集：`xfdmnext` 一条线路没有显示可解码画面，另一条连接超时。这只能证明本次浏览器播放失败，未确认具体编码，不把成功取得媒体地址写成成功播放。

补齐浏览器失败后的自动恢复：本集失败的源站播放页只在当前番剧/当前集内跳过，不会被后续成功的目录检查重新选中；保留规范集数和已确认的观看进度。连续失败最多自动更换 3 次，整个恢复过程共用 90 秒找源预算，停止按钮取消后不再续试。明确手动重新解析允许重试；“自动寻找其他源”仍跳过本集失败页面。无集数身份和自定义视频不会触发无关的番剧搜索。

同时修复初始画面等待期间暂停被误判失败，以及自动搜索耗尽后“重新解析”校验空地址的问题。媒体错误按网络、解码、不支持格式和 HLS 请求区分；用户取消请求不触发换源。已有目录状态不覆盖刚记录的播放失败。

回归检查：`scripts/check-playback-recovery.cjs` 验证集数隔离、次数、总预算、取消和手动重试；`scripts/check-player.cjs` 直接执行生产找源/错误处理代码，覆盖浏览器失败后跳过该页并保留第 2 集/41 秒、旧播放器错误被忽略、暂停后恢复检测及空地址重试。

刷新观看页的线上验收还发现元数据副作用会重置正在恢复的源，并取消刚发出的分集请求。改为仅初始化普通详情；恢复观看时保留视频源/线路，元数据清理只取消自身请求。关闭详情仍明确取消源站请求。增加真实生产副作用与关闭处理的回归检查。

补充验收覆盖“元数据先返回、源站分集后返回”的相反加载顺序。分集变更也会在绘制前按元数据校准，且重复校准保持原引用，避免刷新后第 29 集与侧栏第 1 集混用或产生渲染循环。

## 继续补齐：以图搜番与详情体验

继续对照相同上游 main：`lib/request/apis/trace_api.dart`、`lib/pages/search/image_search_page.dart` 和原生隐身观看设置。

- 以图搜番接在发现页，选择图片只产生本机预览，点击“开始识别”后才处理并发送。支持 JPG/PNG/WebP，输入最大 5 MB，最长边缩至 1280、导出 JPEG 最大 1 MB；不附带原文件名，Canvas 重绘不保留原文件元数据。
- 浏览器使用匿名 multipart POST 直接请求固定的 `https://api.trace.moe/search?anilistInfo=2`，不携带本站 Cookie、凭证或 Referer，禁止自动跟随重定向。本站服务器不接收图片，不在 D1/R2 或本地持久化存储中保存图片和识别结果。这样不会把所有访客集中到本站服务器同一份 IP 配额。
- 返回数据限制 256 KB，最多解析 100 条、展示 8 个候选，优先展示服务已有中文译名、用原名回本站搜索；只显示具有非成人标记的有效 AniList 动画元数据，合并同作品同集的重复结果。相似度明确标注为候选，不承诺准确识别。服务提供的任意图片/视频 URL 不直接加载。
- 手动选候选标题后，清除旧的高级条件、年份和标签，再走本站现有 Bangumi 搜索及片源流程。未假造 AniList 与 Bangumi ID 的对应，也不把匹配成功当作已找到可播放资源。
- 停止、关闭面板、替换图片或离开页面都会取消当前任务；处理/识别的旧回调不能覆盖新图片的结果。处理用地址完成后释放；预览地址在换图、清除或离开时释放。配额、服务繁忙、网络/CORS、无结果、异常数据分别给出可理解的提示。
- 人物资料改为角色/声优与制作人员切换，可按姓名、职务、声优筛选。首次展开按需获取，成功加载后折叠/再展开复用当前资料，部分失败可明确重试；避免几十个角色把导演信息推到很远的位置。
- 修复隐身观看中途关闭时无记录可更新的问题：只为当前正在播放的同一媒体恢复记录，在下一次确认进度时创建断点；切线旧回调仍无效。其他标签页正常删除历史不会被普通进度回调重新创建。跨标签页开关同样生效，且不重复写入开关。

验证：`scripts/check-discovery-continuation.cjs` 执行生产识别数据处理、本地压缩、实际上传组件的显式提交/取消/去重、人物组件切换/筛选/缓存及 Home 的隐身切换进度回调；原有类型、D1/账户同步、规则、缓存、安全、目录及播放器检查继续通过。线上识别验收只使用 trace.moe 官方文档中公开的演示图片，不上传聊天附件、私人截图或用户资料。

服务依据：[官方 API 文档](https://soruly.github.io/trace.moe-api/)、[API 用法源码](https://github.com/soruly/trace.moe-api/blob/master/docs/docs.md)、[官方配额说明](https://github.com/soruly/trace.moe-api/blob/master/docs/limits.md)。免费接口的可用性和配额由服务方决定，本站不规避限额。
