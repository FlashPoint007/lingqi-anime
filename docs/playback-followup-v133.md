# 播放与片源交互复查（2026-11-14）

基线为线上 v132。此次继续处理实际云浏览器验收发现的两个问题；保留上一版的 Kazumi 2.4.4 规则适配、自定义定时暂停和“今晚看什么”。

## giriGiriLove 动态播放页

上游 2.7 规则生成的 Atom 播放页可读取，但页面本身没有视频字面量，只有 `APlayer` 容器和外部播放器脚本，原静态解析器因而返回“未解析到可播放的视频地址”。这是网页端解析兼容性缺口，不是分集目录或访问授权失败。

公开 HTTP 核验确认脚本从当前地址的 `url` 查询参数读取媒体。适配限定官方规则与固定播放页路径；服务端必须先从当前上游分集目录生成并完整匹配该播放页，成功读取页面并识别 Atom 容器后，才使用参数中的公共 HTTPS 媒体。保持原有验证页识别、媒体检查与逐跳重定向检查，不运行远端 JavaScript，不信任客户端的授权标记。

## 片源按钮不再随检测结果移动

原界面每收到一项检测结果就重新排序，同时新增消息行改变卡片高度，可能导致用户指向 giri 时实际点击到已移过来的 LMM。

列表现在保持当前顺序，检测状态和成功率仍实时更新；用户可主动“按最新结果排序”。“有分集”筛选下新结果追加末尾，消息和统计行预留固定高度。自动选源仍使用实时成功率与起播耗时排序。账号、番剧与规则范围变化会使旧点击回调失效。
